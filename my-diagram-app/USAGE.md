# My Diagram App - 使用方法 (USAGE)

このドキュメントでは、`My Diagram App` のセットアップ手順と使い方を説明します。

---

# Part I: セットアップ

## 1. 前提条件

- **Node.js**: v18.x 以上を推奨
- **npm**: Node.js に付属
- **Git**: プロジェクトのクローンに必要
- **AIアシスタント** (任意): Claude Desktop など、Model Context Protocol (MCP) に対応したAIクライアント

### 1.1 Node.js のインストール

[Node.js 公式サイト](https://nodejs.org/) から LTS 版をダウンロードしてインストールしてください。

インストール後、以下のコマンドでバージョンを確認します。

```bash
node -v
npm -v
```

`v18.x` 以上が表示されれば準備完了です。

## 2. プロジェクトのセットアップ

### 2.1 プロジェクトの取得

まず、このリポジトリをローカルにクローンまたはダウンロードします。

```bash
# Gitを使用する場合
git clone <リポジトリのURL> my-diagram-app
cd my-diagram-app
```

### 2.2 依存関係のインストール

社内ネットワーク等でプロキシを使用している場合は、先にnpmにプロキシを設定してください。

```bash
npm config set proxy http://proxy-server:8080/
npm config set https-proxy http://proxy-server:8080/
```

> プロキシが不要な環境ではこの手順はスキップしてください。

プロジェクトのルートディレクトリで、必要な依存関係をインストールします。

```bash
# プロジェクトのルートディレクトリ (my-diagram-app) で実行
npm install
```

次に、MCPサーバーの依存関係をインストールします。

```bash
# mcp-server ディレクトリに移動
cd mcp-server
npm install

# ルートディレクトリに戻る
cd ..
```

## 3. アプリケーションの起動

### 3.1 まとめて起動する方法（推奨）

プロジェクトには、3つのサーバーを同時に立ち上げるための便利なスクリプトが用意されています。

```bash
# プロジェクトのルートディレクトリ (my-diagram-app) で実行
npm run start:all
```

このコマンドを実行すると、`concurrently` によって以下の 3 つが並列に起動し、ログが色分けされて一つのターミナルに表示されます。

| プロセス | ポート | 役割 |
|----------|--------|------|
| Yjs 同期サーバー | 1234 | ブラウザ⇔MCPサーバー間のデータ同期 |
| フロントエンド (Vite) | 5173 | ブラウザで操作するReactアプリ |
| MCPサーバー | 3000 | AIアシスタントからの図面操作を受付 |

> **トラブルシューティング**: 
> もし `'cross-env' は、内部コマンドまたは外部コマンド...` というエラーが発生した場合は、依存関係が未インストールです。
> プロジェクトのルートディレクトリで `npm install` を実行してください。

### 3.2 個別に起動する場合

各プロセスを別々のターミナルで起動して詳細なログを確認したい場合は、以下の手順で行います。

#### ターミナル1: Yjs 同期サーバー

```bash
npx y-websocket
```
*   `ws://localhost:1234` で接続を待ち受けます。

#### ターミナル2: フロントエンド

```bash
npm run dev
```
*   `http://<サーバーのIPアドレス>:5173/` をブラウザで開いてください。

#### ターミナル3: MCPサーバー

```bash
cd mcp-server
node index.js
```
*   `http://0.0.0.0:3000/sse` で接続を待ち受けます。

## 4. AIアシスタントの接続設定

AIアシスタントが MCP サーバーを認識できるように、設定ファイルを編集します。

### 4.1 Claude Desktop の設定

設定ファイル（`claude_desktop_config.json`）を編集します。

- **Windows**: `%APPDATA%\Claude\claude_desktop_config.json`
- **macOS**: `~/Library/Application Support/Claude/claude_desktop_config.json`

以下の内容を `mcpServers` セクションに追記または更新します。

```json
{
  "mcpServers": {
    "diagram-app": {
      "url": "http://localhost:3000/sse" 
    }
  }
}
```

**重要**: 設定ファイルを保存した後、**Claude Desktop を必ず再起動**してください。

## 5. 動作確認

1.  すべてのプロセスが正常に起動していることを確認します（セクション3参照）。
2.  ブラウザで `http://localhost:5173/` を開き、画面が表示されることを確認します。
3.  AI連携を使用する場合は、AIクライアントからツール一覧に `diagram-app` が表示されることを確認します。

# Part II: 使い方ガイド

## 6. 画面構成と基本操作

### 6.1 プロジェクト管理

アプリは**マルチプロジェクト**に対応しています。プロジェクトごとにデータが完全に分離されます。

- **プロジェクト切り替え**: 画面上部のグローバルコマンドバーのプロジェクト名をクリック → プロジェクトブラウザが開きます。
- **プロジェクト名の変更**: プロジェクト名をダブルクリックしてインライン編集。
- **新規プロジェクト作成**: プロジェクトブラウザの「新規作成」ボタン。

### 6.2 グローバルコマンドバー

画面最上部のバーから主要な操作を実行できます。

| ボタン | 機能 |
|--------|------|
| プロジェクト名 | クリック: プロジェクトブラウザ / ダブルクリック: 名前編集 |
| 図を開く | 既存ブロック図の一覧からタブで開く |
| 図を追加 | 新しいブロック図を作成してタブで開く |
| ビュー追加 ▾ | ドロップダウンからビュータイプを選択してタブ追加 |

### 6.3 タブとマルチビュー

VS Code風のタブバーで複数のビューを同時に開けます。

| 操作 | 説明 |
|------|------|
| クリック | タブ切り替え |
| ダブルクリック | タブ名のリネーム |
| ×ボタン | タブを閉じる |
| ドラッグ＆ドロップ | タブの並び替え |
| 右クリック | 「閉じる」「これ以外を閉じる」「すべて閉じる」 |

**ビュータイプ**:
- **ノードグラフ**: ツリー構造でノードとエッジを操作するメインビュー。
- **一覧表**: ノードデータのスプレッドシート表示。右クリック→「図を開いてフォーカス」で対象ノードにジャンプ。
- **ブロック図**: シェイプ（矩形・ひし形・楕円等）を自由配置。色・サイズ変更可能。
- **ファンクションフロー**: （プレースホルダ、今後実装予定）

## 7. ノードグラフの操作

| キー/操作 | 説明 |
|-----------|------|
| `Ins` | 選択ノードの子ノードを追加 |
| `Enter` | 兄弟ノードを追加 |
| `Shift+Enter` | ノードを上へ挿入 |
| `Shift+Ins` | ノードを左へ挿入 |
| `Delete` | 選択ノード/エッジを削除 |
| `Ctrl+↑/↓` | 兄弟ノードの順序入れ替え |
| `Ctrl+←/→` | 階層の上げ下げ |
| `F2` | ノード名のインライン編集 |
| 文字キー | ノード選択中に押すと即座に編集モード開始 |
| 複数選択→右クリック | ブロック図への一括追加メニュー |

## 8. ブロック図の操作

- **シェイプ変更**: ノード選択時に表示されるシェイプ選択UIから変更。
- **色変更**: 背景色・枠線色・文字色をカラーピッカーで変更。
- **リサイズ**: ノード右下のハンドルをドラッグ。
- **エッジ追加**: ツールバーのエッジ追加モードを使用。ラバーバンド表示で接続先をプレビュー。

## 9. AI連携 (MCP) の使い方

MCPサーバー経由で、AIアシスタントが図面を直接操作できます。複数のAIクライアントが同時接続可能です（SSEトランスポート）。

### 9.1 利用可能なツール

#### プロジェクト管理

| ツール名 | 説明 | 必須パラメータ |
|----------|------|----------------|
| `list_projects` | フロントエンドに登録されたプロジェクト一覧を取得（IDとroomName付き） | なし |
| `switch_project` | プロジェクトを切り替え（ルーム名はレジストリから自動解決） | `projectId` |
| `current_project` | 現在接続中のプロジェクト情報を取得 | なし |

#### ノードグラフ操作

| ツール名 | 説明 | 必須パラメータ |
|----------|------|----------------|
| `read_graph` | 全ノード・エッジを取得 | なし |
| `add_node` | ノードを追加 | `label` |
| `connect_nodes` | 2ノード間にエッジを作成 | `source`, `target` |
| `update_node` | ノードのラベル/クラスを更新 | `id` |
| `delete_node` | ノードと関連エッジを削除 | `id` |

#### ブロック図操作

| ツール名 | 説明 | 必須パラメータ |
|----------|------|----------------|
| `list_diagrams` | ブロック図一覧を取得 | なし |
| `read_diagram` | ブロック図のレイアウト付きデータを取得 | `diagramId` |
| `add_node_to_diagram` | ブロック図にノードを配置（新規/既存） | `diagramId` |
| `add_edge_to_diagram` | ブロック図にエッジを追加 | `diagramId`, `source`, `target` |

#### プロジェクト名操作

| ツール名 | 説明 | 必須パラメータ |
|----------|------|----------------|
| `get_project_name` | プロジェクト名を取得 | なし |
| `update_project_name` | プロジェクト名を更新 | `name` |

### 9.2 ノードクラス

`add_node` / `update_node` の `nodeClass` パラメータで、ノードの種別を設定できます。

- `Requirement`, `Spec`, `Design`, `Issue`, `DB`, `Process`

### 9.3 使用例

AIアシスタントに以下のような自然言語で指示できます。

```
「プロジェクト一覧を見せて」            → list_projects
「プロジェクト proj_default に接続して」 → switch_project(projectId: "proj_default")
「現在の図面の内容を教えて」        → read_graph
「"ログイン機能"というノードを追加して」 → add_node(label: "ログイン機能")
「node-1 と node-2 を接続して」     → connect_nodes(source: "node-1", target: "node-2")
「node-1 のラベルを"認証機能"に変更して」→ update_node(id: "node-1", label: "認証機能")
「node-3 を削除して」              → delete_node(id: "node-3")
「ブロック図の一覧を見せて」         → list_diagrams
「default図面の内容を読んで」        → read_diagram(diagramId: "default")
「ブロック図にnode-1を配置して」      → add_node_to_diagram(diagramId: "default", nodeId: "node-1")
```

> **重要**: MCPサーバーは起動時に未接続状態です。最初に `list_projects` でプロジェクト一覧を取得し、`switch_project` で接続してから他のツールを使用してください。プロジェクト一覧が空の場合は、フロントエンド（ブラウザ）が起動しているか確認してください。
