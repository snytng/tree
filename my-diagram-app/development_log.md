# 開発ログ

## 1. プロトタイプ初期フェーズ (2024-XX-XX)

### 1.1 プロジェクトの開始
React Flowを使用して「ホワイトボードのように自由で、かつグラフDBのような意味論を持つ」モデリングツールのプロトタイプを作成開始。

### 1.2 初期モックの動作確認
Vite + React + React Flowで、ノード（四角）とエッジ（線）を動的に追加・接続できる最小構成のモックが動作済み。
ユーザーは「最初はスキーマレスに、徐々に構造化（属性定義）」していく成長型のツールを目指している。

### 1.3 共同編集機能の検討
次のステップとして、このプロトタイプを「共同編集（リアルタイム同期）」に対応させることを決定。

#### 1.3.1 技術スタックの選定
- 同期エンジン: Yjs (CRDT) を使用。
- 通信: まずはサーバー不要でブラウザ間通信ができる y-webrtc 、または簡単なバックエンドで済む y-websocket を想定。

#### 1.3.2 実装要件
- nodes と edges の状態を Yjs の Y.Doc で管理し、複数タブ/ブラウザ間でリアルタイムに同期させる。
- React Flow の onNodesChange や onEdgesChange を Yjs の共有型（Shared Types）と連動させる。

#### 1.3.3 実装依頼
この構成を実現するための、App.jsx の修正案と必要なライブラリのインストールコマンドを依頼。

- **原因**: `npx y-websocket` がルートディレクトリで実行された際、`y-websocket` が `mcp-server/package.json` の依存関係にしか存在しなかったため、実行可能ファイルが見つからなかった。

- **対応**: `npm install` をルートディレクトリで再実行することで、`y-websocket` コマンドが `npx` から利用可能になる。

## 2.31 ノード直接移動のバグ修正と安定化 (2026-04-28)
- **事象**: ドラッグ＆ドロップ時にエッジの張り替えが発火しない、または手動モードで座標が戻る問題が発生。
- **原因特定**: 
    1. React Flow v11 のイベント名が `onNodeDragStop` であるべきところが `onNodeDragEnd` になっていた。
    2. 手動モード時にノードの `width`/`height` 情報が欠落し、交差判定 (`getIntersectingNodes`) が失敗していた。
    3. 交差判定がデフォルトで完全包含を求めていた。
- **解決策**: イベント名の修正、`syncState` での固定サイズ注入、判定時の `partially=true` オプション導入により、手動・自動両モードでの安定動作を確認。
