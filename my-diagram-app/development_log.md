# 開発ログ

## 1. プロトタイプ初期フェーズ (2024-XX-XX)

### 1.1 プロジェクトの開始
React Flowを使用して「ホワイトボードのように自由で、かつグラフDBのような意味論を持つ」モデリングツールのプロトタイプを作成開始。

### 1.2 初期モックの動作確認
Vite + React + React Flowで、ノード（四角）とエッジ（線）を動的に追加・接続できる最小構成のモックが動作済み。
ユーザーは「最初はスキーマレスに、徐々に構造化（属性定義）」していく成長型のツールを目指している。

### 1.3 共同編集機能の検討
次のステップとして、このプロトタイプを「共同編集（リアルタイム同期）」に対応させることを決定。

#### 1.3.1 技術スタックの選定
- 同期エンジン: Yjs (CRDT) を使用。
- 通信: まずはサーバー不要でブラウザ間通信ができる y-webrtc 、または簡単なバックエンドで済む y-websocket を想定。

#### 1.3.2 実装要件
- nodes と edges の状態を Yjs の Y.Doc で管理し、複数タブ/ブラウザ間でリアルタイムに同期させる。
- React Flow の onNodesChange や onEdgesChange を Yjs の共有型（Shared Types）と連動させる。

#### 1.3.3 実装依頼
この構成を実現するための、App.jsx の修正案と必要なライブラリのインストールコマンドを依頼。

## 2. ドキュメント連携とプロジェクト管理フェーズ (2024-XX-XX)

### 2.1 ドキュメント・トレーサビリティの実装
- `spec.md` および `design.md` から ID `[S-xxx]`, `[D-xxx]` を動的に抽出するパーサーを実装。
- `mapping.json` に基づき、要件と設計の依存関係をキャンバス上に自動構築する機能を導入。

### 2.2 プロジェクト入出力 (ZIPパッケージング)
- `jszip` を導入し、Markdownファイル群と `mapping.json` を一括でインポート/エクスポートする機能を実装。
- インポート時にプロジェクト名を自動識別し、画面上に表示・同期するメタデータ管理を導入。
- 自動レイアウト（Dagre）とカメラ制御（fitView）の連動により、インポート直後の視認性を向上。

### 2.3 操作性と視認性の向上フェーズ (2024-XX-XX)
- **[D-014] キーボードナビゲーションの実装**: 
    - 矢印キーで視覚的に最も近いノードへフォーカスを移動するカスタムフック `useKeyboardNavigation` を導入。
    - 軸のズレに重みを付けた距離計算ロジックを採用し、直感的な移動を実現。
- **[D-015] ノード形状の安定化**:
    - ノードサイズを `180x60` に固定。自動レイアウト時の計算の不確実性を排除。
- **レイアウトアルゴリズムのブラッシュアップ**:
    - 再帰的領域スタッキングにおいて、親ノードが常に子ノード群の垂直方向中央に配置されるよう計算式を修正。
- **プロジェクト構造の整理**:
    - Reactの流儀に従い、カスタムフックを `src/hooks/` ディレクトリへ配置。

### 2.4 構造編集機能の検討 (2024-XX-XX)
- **[B-004] 構造的ツリー編集の提案と吟味**:
