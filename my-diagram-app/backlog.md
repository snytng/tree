# My Diagram App バックログ (Backlog)

## ステータス定義
- [ ] **Todo**: 未着手。要件定義や設計から開始する必要がある。
- [R] **Ready**: 準備完了。テスト仕様が定義され、ユーザーの確認が済んだ状態。
- [/] **Doing**: 進行中。現在実装または設計の詰めを行っている。
- [T] **Testing**: 実装は完了し、ユーザーによる実機テスト・承認待ちの状態。
- [x] **Done**: 実装・テスト完了。

---

## 1. [x] [B-001] インライン編集機能 (Inline Editing) - Done
- **概要**: ノードをダブルクリックすることで、その場でタイトル（ラベル）を編集できる機能。
- **目的**: Markdownファイルを直接書き換えなくても、キャンバス上で直感的に思考を具体化できるようにする。編集内容は Yjs を通じて `projectFiles` (spec.md/design.md) に書き戻す。

## 2. [ ] [B-002] 詳細表示パネル (Detail Panel)
- **概要**: 選択中のノードの ID に対応する Markdown セクションの全文を画面右側のサイドパネルに表示する機能。
- **目的**: 図面上の「ハコ」と、その背景にある「詳細な仕様・設計内容」をシームレスにリンクさせ、トレーサビリティを体現する。

## 3. [ ] [B-003] オートレイアウト中の手動位置微調整 (Manual Tweaks in Auto-Layout)
- **概要**: 自動レイアウトが ON の状態でも、特定のノードに対してユーザーが手動でオフセット（微調整）を加えられるようにする。
- **目的**: 基本的な整列はアルゴリズムに任せつつ、「このノードだけは少し離したい」といった人間の感性によるレイアウト調整を許容する。

## 4. [x] [B-004] 構造적ツリー編集ショートカット (Structural Tree Shortcuts) - Done
- **概要**: `Ctrl + 矢印キー` を使用して、フォーカス中のノードをツリー構造内で移動させる機能。
    - [x] **Enter / Ctrl + Up/Down**: 兄弟ノードの追加と順序入れ替え（Done: [S-016]）。
    - [x] **Ctrl + Right**: 上にある兄弟ノードの子ノードに移動（階層を下げる / Done）。
    - [x] **Ctrl + Left**: 親ノードの弟ノードに移動（階層を上げる / Done）。
- **ルール**: 移動時は子ノード（サブツリー）をすべて引き連れて移動する。
- **目的**: マウスを使わずに、アウトライナー感覚で図面の論理構造を高速に組み替えられるようにする。

## 5. [x] [B-005] ノードとノードの間のエッジをノードを２回クリックするだけで追加 - Done
- **概要**: エッジ編集モードを導入し、エッジ編集モードに入ったときには、Fromノードをクリック、Toノードをクリックすることでエッジを引ける機能。

## 6. [B-006] エッジ名のインライン編集
- **概要**: エッジをダブルクリックすることで、その場でタイトル（ラベル）を編集できる機能。

## 7. [B-007] ノードの色
- **概要**: ノードのクラス（属性）を定義し、ノードの属性に応じて色付けする機能。

## 17. [B-0017] ノードの形状
- **概要**: ノードのクラス（属性）を定義し、ノードの属性に応じて形状を変えるる機能。

## 8. [x] [B-008] ノードの直接移動 - Done
- **機能**: ノードを今の親から切り離し、別のノードに近づけるとその子ノードに、エッジに近づけるとその間に割り込むように移動できる機能。
- **目的**: ノードの移動をハンドルでつけ変える操作は細かいノードをつかむためコストを抑えるため

## 9. [ ] [B-009] Undo 履歴の最適化 (Undo Atomicity)
- **概要**: エッジ追加（2クリック）や複雑な構造変更を、1回の Undo で元に戻せるようにトランザクションを設計し直す。
- **目的**: ユーザー操作の直感的な「一歩戻る」を実現する。

## 10. [x] [B-010] プロジェクト名の編集 - Done
- **概要**: プロジェクト名を編集できる機能。エクスポート時のデフォルト名としても利用される機能。

## 11. [B-011] ノードの作成直後の即時ノード名編集
- **概要**: ノードを追加した直後にアルファベットを入力するとインライン編集を開始する機能

## 12. [x] [B-012] ノードを上へ挿入機能 - Done
- **概要**: 選択しているノードの上にノードを追加する機能。Enterで挿入する位置の反対の動作。ノードが上にがある場合には選択ノードとの間に挿入する。

## 13. [x] [B-013] ノードを左へ挿入機能 - Done
- **概要**: 選択しているノードの左にノードを追加する機能。Insで挿入する位置の反対の動作。親ノードがある場合には選択ノードと親ノードのの間に挿入する。結果として親ノードと選択ノードのエッジは削除される。

## 14. [x] [B-014] レイアウトプレビュー (Ghost Node) - Done
- **概要**: ノード追加時に即座に配置するのではなく、マウスカーソルにノードが吸着した状態（プレビュー）にし、ユーザーが納得した地点でクリックして配置を確定させる機能。
- **目的**: 思考を中断せずに、配置場所を「探りながら」決定できる直感的なUIを提供し、自由な発想を支援する。

## 15. [ ] [B-015] 構造操作ロジックのリファクタリングとテスト強化
- **概要**: `onAddStructuredNode` や座標計算ロジックを純粋関数として抽出し、コンポーネントから独立させる。
- **目的**: 機能が複雑化しても安定性を維持し、「驚きを与えるような新機能」を迅速かつ安全に実装できる盤石な基礎を作る。

## 16. [x] [B-016] 選択ノードに関連するノードのみを表示
- **概要**: 選択しているノードに対してつながっているノードだけを一時的に表示でき、解除できる。左右どちらも、右側だけ、左側だけ、一つずつ展開、一つずつ折りたたむなどキー操作で見たいものだけをフィルター表示する機能。

## 18. [x] [B-018] MCPサーバー (Model Context Protocol) - Done
- **概要**: 外部の AI アシスタントが図面のノードやエッジを直接操作できる MCP サーバーを実装する。
- **目的**: AI に「この仕様に基づいて図面を更新して」「関連するノードを接続して」といった指示を出し、図面と AI の双方向連携を実現する。

## 19. [x] [B-019] インポート、エクスポート機能の改善 - Done
- **概要**: 外部連携しやすくするために、zipファイルでの入出力でなく１ファイルのテキストでできる機能

## 20. [ ] [B-020] 複数ノードの移動
- **概要**: 複数ノードを選択して一度に移動する機能

## 21. [ ] [B-021] エッジにノードをドラッグドロップ
- **概要**: エッジにノードをドラッグドロップしたらその間に挿入される機能（以前実装したと言っているけど全く実装されていないので備忘録で追記した）

## 22. [x] [B-022] 階層テキストのコピペ機能 - Done
- **概要**: クリップボードへコピーされたテキストからノードを追加、または選択ノードをテキストとしてコピーできる機能。
- **目的**: Excelやアウトライナー等、外部ツールとの迅速な情報交換を可能にする。

## 23. [ ] [B-023] Dangling Edges の自動削除
- **概要**: Markdown ファイルをインポートする際、`## Nodes` セクションに存在しないノード ID を参照しているエッジ（Dangling Edges）を自動的にフィルタリングし、削除する。
- **目的**: インポート後の図面データ整合性を確保し、無効なエッジがキャンバス上に残ることを防ぐ。
- **詳細**: `parseMarkdown` 関数でノードとエッジを生成した後、エッジの `source` および `target` が生成されたノードリストに存在するかを検証する。存在しない場合はそのエッジを破棄する。
