# My Diagram App 設計書

## 1. [D-001] 技術スタック詳細
- **Frontend**: React (Vite)
- **Diagramming**: React Flow
- **CRDT**: Yjs (Y.Doc, Y.Map)
- **Network**: y-webrtc (Signaling over public server)
- **Storage**: y-indexeddb
- **Layout**: Dagre

## 2. [D-002] データ構造と同期アルゴリズム（セレクションのローカル化）
- `ydoc.getMap('nodes')` および `ydoc.getMap('edges')` を使用して要素を管理。
- **トランザクションオリジンの使い分け**:
    - `'local'`: 選択状態の変更、ドラッグによる移動（自動レイアウトOFF時）など、再レイアウトを必要としない操作に使用。
    - `'structural'`: ノード・エッジの追加・削除、接続の変更、順序の入れ替えなど、グラフ構造の変化を伴う操作に使用。`syncState` はこのオリジンを検知して再レイアウトを実行する。
- **ローカル状態の保護**: `selected` プロパティは Yjs の共有 Map には保存しない。
- **マージロジック**: `syncState` において、Yjs から受信したノードデータと React の現在の `nodes` ステートを ID で照合し、`selected` フラグを React 側から維持する。
## 3. [D-003] カスタムノード実装
- `Handle` コンポーネントを `Position.Left` (Target) と `Position.Right` (Source) に配置。
- `nodeTypes` に登録し、`default` タイプを上書きすることで既存データとの互換性を確保。

## 4. [D-004] 自動レイアウト計算
- **再帰的領域スタッキング (Recursive Box Stacking)**:
    - **ボトムアップ高さ計算**: 各ノードについて、その子孫ノード全てを収容するために必要な垂直方向の「箱（Box）」の総高さを再帰的に計算する。
    - **垂直スタッキング**: 兄弟ノード（同じ親を持つ子たち）を、現在の物理的な垂直座標（y）の順序で、計算された「箱」の高さに基づいて隙間なく積み上げる。
    - **ソートの安定性**: 共有データ上の座標（y）を唯一の順序基準とする。座標が同一の場合は ID による文字列比較をタイブレイカーとして使用する。
    - **論理的中間座標（Midpoint Insertion）**: ノード挿入時（Enter/Insert）、選択ノードと次のノードの `y` 座標の中間値を計算して割り当てることで、既存の構造を壊さずに論理的な「直下」への挿入を保証する。
    - **親のセンタリング**: 親ノードは、自身の子たちが占有する「箱」の垂直方向の中央に配置する。
    - **共有ノードの処理**: 複数の親を持つノードは、最初に到達した（垂直位置がより高い）親の家系図に専有させる。
- **レイアウト定数**: `horizontalStep: 360` (ノード幅180 + 間隔180), `verticalGap: 40`。
- 自動モード時も `nodesDraggable: true` とするが、Shiftキーなしの移動は Yjs に保存しない。
- **モード移行時の永続化**: 自動レイアウトをOFFにする際、その時点の計算済み座標を `yNodes` に一括書き込みし、レイアウトを維持する。
- **一貫したレイアウトと堅牢性**: ノードやエッジの追加・削除・接続時、自動レイアウトがONであれば常にグラフ全体を再計算する。計算時、存在しないノードを参照する「宙ぶらりん（dangling）」なエッジは無視し、ランタイムエラーを防止する。
- **削除の連動**: ノード削除時、そのノードに接続されているエッジも同時に削除し、グラフの整合性を維持する。

## 12. [D-012] Undo/Redoボタンの実装

- `UndoManager` の `stack-item-added` および `stack-item-popped` イベントを監視し、`canUndo()` と `canRedo()` の結果を React のステートで管理。
- ボタンの `disabled` 属性とスタイル（透過度、カーソル、ボーダー色）をステートに応じて動的に変更。

## 13. [D-013] レイアウトデバッグの実装
- 現在の `nodes` ステート（ID, label, nodeClass, position）と `edges` ステート（source, target）を JSON 形式で集計。
- `navigator.clipboard.writeText` を用いて、クリップボードへのコピー機能を実装。
- ツールバーにデバッグ用アイコンボタンを追加。
- **動的フィルタリング**: 
    - 1つ以上のノードを選択している場合、選択中のノードとそのノード間を繋ぐエッジのみを出力対象とする。
    - 各ノードの属性 (`nodeClass`) を JSON 出力に含めることで、解析を容易にする。
    - 何も選択していない場合は、図面全体のデータを出力する。

## 14. [D-014] キーボードナビゲーションの実装
- 以下の判定ロジックに基づき、`keydown`（ArrowUp/Down/Left/Right）イベントで選択ノードを移動する：
    - **ターゲットの絞り込み**: 押されたキーの方向にあるノードのみを候補とする（例：`ArrowRight` なら現在地より X 座標が大きいノード）。
    - **距離スコア計算**: 次の式で最小スコアのノードを選択する。
        - `Score = (主軸の差) + (副軸の差 * 重み)`
        - 重みを `2.5` 程度に設定することで、軸が揃っているノードを強く優先する。
- 選択移動時は、Yjs のトランザクションを使用して、旧ノードの `selected: false` と新ノードの `selected: true` を一括更新する。

## 15. [D-015] 固定サイズノードと整列アルゴリズムの調整
- `CustomNode` の CSS において `width: 180px`, `height: 60px` などの固定値を適用。
- Dagre レイアウトおよび再帰的領域スタッキング ([D-004]) において、固定サイズを前提とした配置計算を行い、ノードの垂直・水平方向の中心が揃うように調整する。
- 自動レイアウト実行時に `nodesep` (ノード間隔) と `ranksep` (階層間隔) を一定に保ち、水平方向は `horizontalStep` に基づき整列させる。

## 16. [D-016] 兄弟ノードの順序入れ替えロジック
- **兄弟の特定**: 選択ノードをターゲットとするエッジを検索する。
    - 親がいる場合：親を共有する他のターゲットを兄弟とする。
    - 親がいない場合：入力エッジを持たない他の全てのルートノードを「仮想的な兄弟」とみなす。
- **ソートと検索**: 兄弟リストを現在の `y` 座標でソートし、選択ノードのインデックスを特定する。
- **座標の入れ替え**: 
    - `Ctrl + Up`: インデックスが 0 でなければ、一つ上の兄弟と `y` 座標の値を Yjs 上でスワップする。
    - `Ctrl + Down`: インデックスが最後でなければ、一つ下の兄弟と `y` 座標をスワップする。
- **自動レイアウトの再発火**: `yNodes` の更新により `syncState` が走り、新しい `y` 順序に基づいた再配置が行われる。

## 17. [D-017] インライン編集の実装詳細
- **コンポーネント構成**: `CustomNode` 内に `isEditing` ローカルステートを導入。`true` の場合は標準のラベル表示を `<input>` 要素に差し替える。
- **イベントハンドリング**:
    - `onDoubleClick`: `isEditing` を `true` にセット。
    - `onBlur`, `onKeyDown (Enter)`: `isEditing` を `false` に戻し、`yNodes` のデータを更新する。
- **Markdown同期ロジック**: 
    - ラベルが `[ID] タイトル` の形式である場合、`projectFiles` (Y.Map) から該当する Markdown ファイルを特定する。
    - 正規表現を用いて、ファイル内の `## [ID] 旧タイトル` 行を新しいタイトルで置換し、`projectFiles` を更新する。
    - この操作は `origin: 'structural'` で実行し、ドキュメントツリー全体の一貫性を保つ。

## 19. [D-019] エッジ追加モードの実装
- **状態管理**: `App.jsx` に `isEdgeMode` (boolean) と `edgeSourceId` (string | null) のステートを導入する。
- **ハンドリング**: 
    - `onNodeClick`: `isEdgeMode` が有効な場合、`edgeSourceId` が空ならクリックしたノード ID を保存。値があるならその ID から現在のノード ID へのエッジを作成（`onConnect` ロジックを再利用）し、`edgeSourceId` をリセットする。
    - `onPaneClick`: 進行中のエッジ作成をキャンセル（`edgeSourceId` をリセット）する。
- **UIフィードバック**: `edgeSourceId` と一致する ID を持つノードには、`CustomNode` 内で特別なボーダー色を適用するスタイルを動的に注入するか、`data` プロパティを介して通知する。
- **キーボード連携**: `Escape` キー押下時に `isEdgeMode` を OFF にする。
- **構造変更の同期**: `onDeleteSelected` を含む、グラフの構造を変更する全ての操作（追加、削除、接続）で、トランザクションオリジンに `'structural'` を指定する。
- **理由**: `syncState` が `'local'` をスキップする仕様において、自分自身の操作による構造変化（およびそれに伴う再レイアウト）を確実に UI へ反映させるため。

## 20. [D-020] 上方向へのノード挿入ロジック
- **計算アルゴリズム**:
    - `onAddStructuredNode` に `mode: 'sibling-above'` を追加する。
    - 共有データ (Yjs) 上で、選択ノードの直前の兄弟ノードの `y` 座標 (`prevY`) を特定する。
    - 直前にノードがある場合： `targetY = (prevY + currentSharedY) / 2`。
    - 直前にノードがない場合： `targetY = currentSharedY - 10`。
    - この論理的な中間値割り当てにより、自動レイアウト側で安定して「上」への挿入が実現される。

## 21. [D-021] 左方向（親方向）へのノード挿入ロジック
- **スプライス（繋ぎ変え）アルゴリズム**:
    - 1. 選択ノードを入力を受けるエッジ（Incoming Edges）をすべて特定する。
    - 2. 新しいノードを作成する（座標は選択ノードの X - 360, Y を基準）。
    - 3. 各既存エッジに対して：
        - `親 -> 新ノード` のエッジを生成。
        - 元の `親 -> 選択ノード` のエッジを削除する。
    - 4. 全ての変更を一つの `structural` トランザクションで実行し、グラフ構造の整合性を維持する。

## 22. [D-022] フォーカス表示のフィルタリングロジック
- **状態管理**: `focusMode` (none | upstream | downstream | both) を導入。
- **抽出アルゴリズム**:

    - 2. 選択中のノードを起点として、指定された方向（Source側またはTarget側）へグラフを走査（BFS/DFS）し、到達可能なノードIDとエッジIDのセットを作成する。
    - 3. セットに含まれない要素に `hidden: true` プロパティを付与して React Flow に渡す。
- **自動レイアウトとの連携**:
    - `isAutoLayout` が ON の場合、`hidden` ノードはレイアウト計算から除外する（計算対象を可視ノードのみに絞る）ことで、抽出されたツリーを画面中央に再配置する。

## 23. [D-023] MCPサーバーのアーキテクチャ
- **サーバー方式**: Node.js + `@modelcontextprotocol/sdk` を使用した **SSE (Server-Sent Events) 通信**。
- **マルチクライアント管理**:
    - 接続要求 (`/sse`) ごとに新しい `Server` インスタンスを生成し、一意な `sessionId` を持つ `SSEServerTransport` を確立する。
    - アクティブなトランスポートを `Map` オブジェクト (`activeTransports`) で保持し、`/messages` エンドポイントへの POST リクエストを、クエリパラメータの `sessionId` を用いて適切なトランスポートへルーティングする。
    - クライアントの切断 (`res.on("close")`) を検知し、サーバーインスタンスの破棄とトランスポートの削除を行うことでリソースリークを防止する。
- **同期方式 (Yjs Bridge)**:
    - ブラウザ側の同期エンジンを `y-webrtc` から `y-websocket`（または併用）に拡張する。
    - ローカルで `y-websocket` サーバーを起動し、ブラウザと MCP サーバープロセスの両方が同一ルームに参加する。
    - MCP サーバーはヘッドレスな Yjs クライアントとして動作し、共有データを直接書き換える。
- **提供ツールの属性連携**:
    - `add_node` および `update_node` ツールにおいて、[D-043] で定義されたノードクラス（属性）を引数として受け取り、`yNodes` の `data.nodeClass` プロパティへ反映する。
    - **原子性**: 削除操作 (`delete_node`) は `ydoc.transact` 内で実行し、ノードの削除と浮遊エッジ（Dangling Edges）のクリーンアップをアトミックに完了させる。
- **依存ライブラリ**: `ws`, `y-websocket`, `@modelcontextprotocol/sdk`, `express`, `cors`。
- **検証手順 (Test Spec)**:
    - [x] MCP インスペクターまたは Claude Desktop から `read_graph` を呼び出し、現在の図面内容が JSON で返ってくること。
    - [x] `add_node` ツールを呼び出した際、ブラウザ上のキャンバスに即座にノードが出現すること。
    - [x] `add_node` 時の `nodeClass` 指定により、ノードの色とバッジが正しく設定されること。
    - [x] 複数のクライアントが同時に `http://localhost:3000/sse` に接続しても、干渉せず独立して動作すること。
    - [x] 自動レイアウトが有効な場合、AI による編集後も正しく整列されること。

- **イベントハンドリング**:

## 25. [D-025] 階層下げの繋ぎ変えロジック
- **アルゴリズム**:
    - 1. 選択ノードの `parentId` を特定（incoming edge の source）。
    - 2. `parentId` を共有する兄弟ノードを抽出し、現在の `y` 座標でソート。
    - 3. 選択ノードの直前（インデックス -1）にある兄弟ノード `targetParentId` を特定。
    - 4. `targetParentId` が存在する場合、以下の操作を `structural` トランザクションで実行：
        - 選択ノードへの既存エッジを削除。
        - `targetParentId -> 選択ノード` の新しいエッジを追加。
        - 自動レイアウトを維持するため、選択ノードの `y` 座標に微小な値を設定（末尾への配置を促す）。
- **検証手順 (Test Spec)**:
    - [ ] 兄弟ノードが2つ以上ある状態で、下のノードを選択して `Ctrl + Right` を押すと、上のノードの子になること。
    - [ ] ルートノード（親なし）でも、直上に別のルートノードがあればその子になれること。
    - [ ] 移動後、元の親子関係のエッジが消え、新しい親子関係が自動レイアウトで正しく表示されること。

## 26. [D-026] 階層上げの繋ぎ変えロジック
- **アルゴリズム**:
    - 1. 選択ノードの `parentEdge` とそのソース `parentId` を特定。
    - 2. `parentId` に入力エッジがあるか確認し、あればそのソース `grandParentId` を取得。
    - 3. 以下の操作を `structural` トランザクションで実行：
        - `parentEdge` を削除。
        - `grandParentId` が存在する場合、`grandParentId -> 選択ノード` の新しいエッジを追加。
        - 選択ノードの `y` 座標を、元の `parentNode.y + 0.01` に設定する。これにより、自動レイアウト時に元の親の直後に配置される。
- **検証手順 (Test Spec)**:
    - [ ] 親ノードを持つ子ノードを選択して `Ctrl + Left` を押すと、親と同じ階層に移動すること。
    - [ ] その際、元の子ノード（サブツリー）も一緒に階層が上がること。
    - [ ] ルート直下の子ノードを階層上げした場合、新しいルートノードとして独立すること。

## 27. [D-027] ノード直接移動のロジック (Drag-and-Drop Re-parenting Logic)
- **UI/UX**:
    - `onNodeDragStart`: ドラッグ開始時に、ドラッグ中のノードIDを保持するステート (`draggingNodeId`) を設定。
    - `onNodeDrag`: ドラッグ中のノードの座標はReact Flowが自動で更新するため、Yjsには直接書き込まず、ローカルの視覚的な移動のみを行う。
    - `onNodeDragEnd`: ドロップ時に、ドロップ先の要素（ノードまたはエッジ）を特定し、構造変更ロジックをトリガーする。
    - **視覚的フィードバック**:
        - `onNodeDrag` イベント内で、ドラッグ中のノードの下にある要素を `ReactFlow` の `screenToFlowPosition` と `getIntersectingNodes`/`getIntersectingEdges` を利用して特定する。
        - 有効なドロップターゲット（ノード、エッジ）に対して、一時的なCSSクラスを適用してハイライト表示する。
        - `onNodeDragEnd` でハイライトを解除する。
- **ロジック**:
    - **ドロップターゲットの特定**:
        - `onNodeDragEnd` イベント内で、ドロップされた座標 (`event.clientX`, `event.clientY`) を `ReactFlow` の `screenToFlowPosition` メソッドでグラフ座標に変換。
        - 変換された座標と既存のノード/エッジのバウンディングボックスを比較し、ドロップされた要素を特定する。
        - `ReactFlow` の `getIntersectingNodes` や `getIntersectingEdges` を利用して、ドロップ先のノードまたはエッジを効率的に検出する。
    - **構造変更アルゴリズム**:
        - **共通処理**:
            - ドラッグされたノード (`draggedNode`) の既存の親からの入力エッジを特定し、削除する。
            - 全ての変更は `ydoc.transact` を使用し、`'structural'` オリジンで原子的に実行する。
        - **ノードへのドロップ (`targetNode`)**:
            - `targetNode` から `draggedNode` への新しいエッジを作成する。
        - **エッジへのドロップ (`targetEdge` from `edgeSource` to `edgeTarget`)**:
            - `targetEdge` を削除する。
            - `edgeSource` から `draggedNode` への新しいエッジを作成する。
            - `draggedNode` から `edgeTarget` への新しいエッジを作成する。
    - **循環参照の防止**:
        - ドロップ先のノードが、ドラッグされたノードの子孫である場合、ドロップを無効にする。これは、グラフ探索（BFS/DFS）アルゴリズムを用いて子孫関係をチェックすることで実現する。
    - **自動レイアウトとの連携**:
        - `structural` トランザクションにより `syncState` が発火し、自動レイアウトが再計算される。
        - ドロップ後の `draggedNode` の `position` は、自動レイアウトに任せることで、新しい構造に沿って適切に配置される。
- **検証手順 (Test Spec)**:
    - [x] 子ノードをドラッグし、別のノードにドロップすると、そのノードの子になること。
    - [x] ルートノードをドラッグし、別のノードにドロップすると、そのノードの子になること。
    - [x] ノードをドラッグし、既存のエッジにドロップすると、そのエッジの間に挿入されること。
    - [x] ドラッグされたノードの子ノード（サブツリー）も、構造を維持したまま一緒に移動すること。
    - [x] 自身の子孫ノードにドロップしようとすると、操作が無効になること（循環参照防止）。
    - [x] ドロップ後、自動レイアウトが正しく適用され、新しい構造が視覚的に反映されること。
    - [x] ドラッグ中に有効なドロップターゲットが視覚的にハイライトされること。
    - [x] ドロップ先のノードが既にドラッグされたノードの親である場合、操作は無効になること。

## 29. [D-029] ライブ・ローカルレイアウト (Live Local Re-layout)
- **概念**: ドラッグ中、本物のノードをリアルタイムに再配置することで、ゴースト（プレビュー）を不要にする。
- **実行アルゴリズム (onNodeDrag)**:
    - 1. ドラッグ中のノードの現在位置 (`node.position`) を含む暫定的なノード配列を作成。
    - 2. `getLayoutedElements` を実行し、全ノードの「論理的配置」を計算する。
    - 3. **ローカルの React State (`setNodes`) のみを更新**する。
    - 4. ドラッグ中のノード本人のみ、計算値ではなくマウス位置を優先して描画し、操作の連続性を保つ。
- **同期のタイミング**:
    - ドラッグ中は Yjs への書き込みを行わない（ネットワーク負荷軽減）。
    - `onNodeDragStop` (ドロップ) の瞬間に、**ライブレイアウトで計算された全ノードの座標**を `yNodes` に一括書き込みし、他ユーザーへ確定情報を配信する。
- **メリット**: 物理的なマウス位置と論理的な順序が常に一致し、「暴れ」や「ズレ」が根本的に解消される。

## 31. [D-031] 階層テキストの解析と一括挿入ロジック
- **アルゴリズム (Stack-based Parser)**:
    - 1. テキストを改行で分割し、1行ずつ処理。
    - 2. 行頭の空白/タブをカウントして `depth` (深さ) を判定。
    - 3. スタックを利用して「現在の親ノード」を管理。
        - `stack = [{ nodeId, depth: -1 }]`
        - `depth` が増えたらスタックに積み、減ったらスタックを pop する。
    - 4. 判定した親ノード ID と新ノード ID をエッジで接続。
- **原子性の確保**:
    - 全てのノード・エッジ生成は一つの `structural` トランザクション内で実行し、自動レイアウトを1回だけ発火させる。

## 32. [D-032] ツリー構造のテキスト変換ロジック
- **アルゴリズム (Recursive DFS)**:
    - 1. 選択されたノードを起点とする。
    - 2. 深さ優先探索 (DFS) で子孫を走査。
    - 3. `現在の深さ * \t (タブ文字) + ノードのラベル` を配列に蓄積。
    - 4. 配列を `\n` で結合して `navigator.clipboard.writeText` で出力。
- **UI連携**:
    - キャンバスまたはノードがフォーカスされている状態での `Ctrl + C` を検知する。
    - React Flow のデフォルトのコピー挙動（要素の複製）を、この階層テキストコピーで拡張または上書きする。

## 41. [D-041] ノードの視覚的状態と優先順位 (Node Visual Priority)
- **概要**: 複数の状態が重なった際の、枠線や背景色の適用優先順位を定義する。
- **優先順位 (高 → 低)**:
    1. **ドラッグターゲット (`.drag-target-highlight`)**: 青色の太い枠線。構造変更の確定地点を示す。
    2. **モード中ホバー (`.selectable-mode-active :hover`)**: 薄水色の背景。クリック可能な候補であることを示す。
    3. **エッジ接続元 (`.edge-source-candidate`)**: 青色の枠線とグロー。
    4. **プレゼンター選択 (`.presenter-selected`)**: 緑色の枠線と背景。
    5. **ローカル選択 (`.selected`)**: 赤色の枠線。
    6. **デフォルト**: 通常の境界線。
- **設計意図**: 
    - ホバー（操作の意思）は、既存の選択状態（赤）よりも優先して表示することで、ユーザーに「今クリックしたら何が起きるか」を正しく伝える。
    - ただし、エッジの「接続元」として既に確定している青枠は、ホバーで消すと混乱を招く可能性があるため、ホバー背景は適用しつつ枠線は維持する等の調整を行う。

| `addnode` | `edgemode` | **排他** | `addnode` をONにする際、`edgemode` をOFFにし、`edgeSourceId` をクリアする。 |
| `edgemode` | `addnode` | **排他** | `edgemode` をONにする際、`addnode` をOFFにする。 |
| `autolayout` | (全て) | **共存** | 他のどのモードの状態も変更せず、自身のON/OFFのみを切り替える。 |
| `focus` | (全て) | **共存** | 他のどのモードの状態も変更せず、自身の状態遷移 (`none` -> `both` -> ...) のみを実行する。 |

- **共通解除ルール**: 
    - `Escape` キー押下時は、現在有効なすべての「排他モード（`addnode`, `edgemode`）」を解除する。
    - 破壊的操作（`reset`, `import`）の実行前後は、安全のためトグルモードをすべて解除することを推奨。

- **実装への反映ガイド**: 
    - `App.jsx` の `toolbarConfig` 内の `onClick` ハンドラは、本マトリクスに従って副作用（他のステートのセッター呼び出し）を記述すること。

## 43. [D-043] クラスベース・スタイリングの実装
- **パーサーロジック**: `CustomNode` 内で `data.label` を正規表現 `/^\[?([\w\s]+)\]?[:：\s]/` で解析。
- **カラーマッピング**: 
    - `Requirement`: 黄色系
    - `Spec`: 青色系
    - `Design`: 緑色系
    - `Issue`: 赤色系
- **形状マッピング**:
    - `DB`: 境界線を2重にする、または専用アイコン。
    - `Process`: 角丸を大きく設定。
- **CSSの実装**: `CustomNode.jsx` 内で抽出されたクラス名を `data-node-class` 属性として付与し、`App.jsx` の `<style>` でスタイルを定義する。

## 44. [D-044] 属性ベース・スタイリングの優先順位
- **マージロジックの変更**: 
    1. `data.nodeClass` 属性が明示的に存在する場合はそれを最優先する。
    2. 属性がない場合のみ、互換性維持のため `data.label` を解析する（Legacy Fallback）。

## 45. [D-045] 一括属性更新ハンドラ (`onUpdateNodesClass`)
- **引数**: `targetClassName`
- **処理フロー**:
    1. 現在の `nodes` から `selected === true` のものを抽出。
    2. `ydoc.transact` 内で、各ノードの `data.nodeClass` を更新。
    3. 同時に、ラベル内に古いクラス記法があれば正規表現で削除し、文字列を整形する。

## 46. [D-046] ノードクラスの視覚的表示（バッジ）
- **概要**: ラベルから分離された属性情報をユーザーが認識できるよう、ノード内に小さなバッジを表示する。
- **実装**: `CustomNode` の右上に絶対座標で配置。`node-class-xxx` のプレフィックスを除いた短縮名を大文字で表示する。
*※ AIへの指示方法: 上記リストの並びを入れ替えるか、`- (separator) -` を挿入したい場所に記述して指示してください。*

## 47. [D-047] ラバーバンド描画ロジック
- **座標の追跡**:
    - `edgeSourceId` が `null` でない（始点決定済み）とき、`onPaneMouseMove` イベントでマウスのスクリーン座標を取得。
    - `reactFlowInstance.screenToFlowPosition` を用いて論理座標に変換し、ローカルステート `mousePos: { x, y }` を更新する。
- **一時的エッジの注入**:
    - `App.jsx` 内で React Flow に渡す `edges` 配列を生成する際、`edgeSourceId` が存在する場合のみ、末尾に「ラバーバンド用エッジ」を動的に追加する。
    - **プロパティ構成**:
        - `id`: `'rubber-band-edge'` (固定値)
        - `source`: `edgeSourceId`
        - `target`: `'temp-target'` (実在しないID)
        - `type`: `'rubberband'` (専用のカスタムエッジタイプ)
        - `data`: `{ mousePos }`
        - `animated`: `true`
- **カスタムエッジ `RubberBandEdge`**:
    - `getBezierPath`（または `getSimpleBezierPath`）を使用し、`sourceX/Y` から `data.mousePos` までのパスを計算。
    - マウス位置を終点（Target）として強制的に描画する。
- **スナッププレビュー**:
    - マウスが有効な接続先ノード上にある場合、`hoveredNodeId` を更新し、そのノードのハンドルへ吸着した実線に近いプレビューを表示する。
 - **スタイリング**:
    - `.rubber-band-edge-path` クラスを定義。
    - `stroke: #3b82f6` (鮮やかな青), `stroke-dasharray: 5 5` (点線), `opacity: 0.6` を適用。
    - `pointer-events: none` を設定し、マウス操作を邪魔しないようにする。
- **クリーンアップ**:
    - `onNodeClick` による接続完了、`onPaneClick` によるキャンセル、または `Escape` キー押下時に `edgeSourceId` を `null` に戻すことで、ラバーバンドを配列から除去する。
