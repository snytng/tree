# My Diagram App 仕様書

## 1. [S-001] プロジェクト概要
「最初はスキーマレスに、徐々に構造化」していく成長型のモデリングツール。
ホワイトボードのような自由度と、グラフDBのような意味論を兼ね備えたコラボレーションツールを目指す。

## 2. [S-002] 共同編集・同期
- 複数ブラウザ/タブ間でのリアルタイム同期。
- ブラウザをリロードしてもデータが消失しない永続化機能。
- 競合解決（CRDT）に基づいたノード・エッジの管理。

## 3. [S-003] ノードとエッジ
- 左右に接続ポイント（ハンドル）を持つカスタムノード。
- 親子関係を表現するための矢印エッジ。

## 4. [S-004] レイアウトモード
- **自動モード (デフォルト)**: 
    - ルール: 左から右へ配置。親ノードごとに垂直方向の専有領域を確保し、他の親の子ノードと重ならないように配置する。
    - 共有ノード: 親同士で子を共有する場合、垂直方向の順序が上の親の領域に配置し、他の親からは線を跨がせて接続する。
- **手動モード**: ノードの自由なドラッグ＆ドロップが可能。
- トグルボタンによる動的な切り替え。

## 5. [S-005] 操作・UX
- **ノード追加**: 新規ノード生成後、対象を画面中央へ自動パン（移動）させる。
- **選択削除**: 選択中の要素を一括削除。
- **リセット**: 全データを消去して初期化。

## 6. [S-006] 視覚的フィードバック
- 選択状態の強調。
    - ノード: 赤枠とグローエフェクト。
    - エッジ: 赤色化と線の強調。

## 7. [S-007] ドキュメント情報の外部ファイル連携
- インポートされた Markdown ファイルの内容を解析し、IDとタイトルを自動的に抽出する。
- ドキュメントの更新が即座にツールへ反映されるようにする。

## 8. [S-008] プロジェクト・インポート機能
- ZIPファイルまたはフォルダ選択による一括インポート。
- 内部の `mapping.json` と Markdown ファイルを自動識別して取り込む。

## 9. [S-009] プロジェクト・エクスポート機能
- 現在キャンバスに展開されているドキュメント群とリレーションをZIP形式で一括出力。
- 外部ツール（エディタ等）での再利用を可能にする。

## 10. [S-010] プロジェクト情報の可視化
- 現在のプロジェクト名を画面左上のパネルにコンパクトに表示する。
- インポートしたファイル名などを元にプロジェクトを識別可能にする。

## 11. [S-011] アイコンベースの操作インターフェース
- 操作ボタンをテキストからアイコンに変更し、サイズを統一する。
- 各ボタンの機能を説明するためのツールチップ（フローティングウィンドウ）を表示する。

## 12. [S-012] Undo/Redoボタン
- 操作履歴を元に戻す（Undo）およびやり直す（Redo）ためのボタンを追加。
- キーボードショートカット（Ctrl+Z, Ctrl+Y）と連動する。
- これ以上戻せない、またはやり直せない場合にボタンを無効化（グレーアウト）する。

## 13. [S-013] レイアウトデバッグ情報の出力
- 現在の全ノードの座標、エッジの接続関係、レイアウト設定を一括でクリップボードにコピーする機能。
- レイアウトの問題報告や解析を正確に行うための土台として活用する。

## 14. [S-014] カーソルキーによるフォーカス移動
- 矢印キー（上下左右）を使用して、選択中のノードから隣接するノードへフォーカス（選択状態）を移動できる。
- ツリー構造をキーボードのみで効率的に探索可能にする。

## 15. [S-015] ノードサイズの統一と整列の強化
- 全てのノードを固定サイズに統一し、視覚的な一貫性を高める。
- 自動レイアウトにおいて、ノードを上下左右で整列させ、水平方向の間隔を最小化（ノード幅と同等のステップ）したコンパクトな配置を実現する。

## 16. [S-016] 兄弟ノードの順序入れ替え (Ctrl+上下)
- `Ctrl + ArrowUp/ArrowDown` により、選択中のノードとその直上・直下の兄弟ノードの表示順序を入れ替える。
- フォーカス（選択状態）は移動せず、ノードの並び順だけが変わる。

## 17. [S-017] ノードのインライン編集
- **トリガー**: ノードをダブルクリックあるいはF2を押すことで編集モードに移行する。
- **挙動**: 編集モード中はノード内のラベルがテキスト入力フィールド（input/textarea）に切り替わる。
- **確定**: Enterキーの押下、または入力フィールド以外をクリック（Blur）することで変更を確定する。
- **同期**: 変更されたラベルは Yjs を通じて即座に全ユーザーに同期される。
- **Markdown連携**: 編集されたノードがドキュメントのセクション（例: `[S-xxx]`）に対応している場合、`projectFiles` 内の Markdown コンテンツの該当ヘッダー行も自動的に更新される。

## 18. [S-018] クリックによるエッジ追加モード
- **概要**: 連続したノードクリックにより、直感的に接続関係を構築できるモード。
- **トリガー**: 右パネルの「エッジ追加」ボタンでモードをトグル（ON/OFF）する。
- **挙動**: 
    - 1つ目のノードをクリック：接続元（Source）としてマークされる。
    - 2つ目のノードをクリック：接続先（Target）としてエッジが生成される。
    - エッジ生成後、あるいはキャンバス（背景）をクリックすることで選択状態がリセットされる。
- **視覚効果**: 接続元として選択されているノードは、通常時と異なる色（例：青色）で強調される。

## 19. [S-019] ノードを上へ挿入 (Shift + Enter)
- **概要**: 選択中のノードのすぐ上に、同じ親を持つ兄弟ノードを新しく挿入する。
- **トリガー**: `Shift + Enter` キー。
- **挙動**: 
    - 選択ノードの上に別の兄弟ノードがある場合：そのノードと選択ノードの間に挿入される。
    - 選択ノードがその階層の先頭（一番上）である場合：さらにその上に追加される。

## 20. [S-020] ノードを左へ挿入 (Shift + Insert)
- **概要**: 選択中のノードの左側（親方向）にノードを挿入し、既存の親との間に割り込ませる。
- **トリガー**: `Shift + Insert` キー。
- **挙動**: 
    - 選択ノードに親がある場合：親 -> 新ノード -> 選択ノード という接続に組み替え、元の 親 -> 選択ノード のエッジを削除する。
    - 選択ノードがルート（親なし）の場合：新ノード -> 選択ノード のエッジを作成し、新ノードを新たなルートとする。

## 21. [S-021] 関連ノードの抽出表示 (Focus Mode)
- **概要**: 選択中のノードと接続関係にあるノードのみを表示し、他を一時的に隠す。
- **フィルタモード**:
    - **祖先 (Upstream)**: 選択ノードから親方向へ辿れるすべてのノードを表示。
    - **子孫 (Downstream)**: 選択ノードから子方向へ辿れるすべてのノードを表示。
    - **全体 (Full Path)**: 祖先と子孫の両方を表示。
- **操作**:
    - ツールバーの「フォーカス」ボタン、またはショートカットキー `F` でON/OFFを切り替える。
    - フォーカスモード中に選択を切り替えた場合、表示対象も即座に更新される。

## 23. [S-023] プロジェクト名の編集機能
- **概要**: ユーザーがアプリケーションのUIから直接プロジェクト名を編集できる。
- **リアルタイム同期**: 編集されたプロジェクト名は Yjs を通じてリアルタイムに全ユーザー間で同期される。
- **エクスポート連携**: プロジェクトのエクスポート時、ZIPファイルのデフォルト名として編集されたプロジェクト名が使用される。
- **UI**: 画面左上のプロジェクト名表示パネル内で、クリックまたはダブルクリックで編集モードに移行できるようにする。
- **目的**: プロジェクトの識別性を高め、ユーザーが自由に管理できるようにする。

## 24. [S-024] 構造的階層下げ (Indent via Ctrl+Right)
- **概要**: 選択中のノードを、一つ上に位置する兄弟ノードの子要素として移動させる。
- **トリガー**: `Ctrl + ArrowRight` キー。
- **挙動**: 
    - 同一の親を持つノード群の中で、選択ノードの直上の兄弟を特定する。
    - 直上の兄弟が存在する場合、現在の親からのエッジを削除し、「直上の兄弟 -> 選択ノード」という新しいエッジを作成する。
    - 選択ノードが持つ子ノード（サブツリー）は、構造を維持したまま一緒に移動する。

## 25. [S-025] 構造的階層上げ (Outdent via Ctrl+Left)
- **概要**: 選択中のノードを、現在の親ノードと同じ階層（親の弟ノード）に移動させる。
- **トリガー**: `Ctrl + ArrowLeft` キー。
- **挙動**: 
    - 選択ノードの現在の親を特定し、その親から切り離す。
    - 親に親（祖父）がいる場合は、祖父の子にする。親がルートの場合は、自身もルートになる。
    - 常に「元の親のすぐ下」に配置されるよう論理順序を調整する。

## 26. [S-026] ノードの直接移動 (Drag-and-Drop Re-parenting)
- **概要**: Shiftキーを押しながらのドラッグ＆ドロップ操作により、選択中のノードを既存のツリー構造内の別の位置に移動・再接続させる。
- **トリガー**: **Shiftキーを押した状態**でのドラッグ開始から終了までの一連の操作。
- **挙動**:
    - **ドラッグ中**:
        - 有効なドロップターゲット（他のノード、エッジ）が視覚的にハイライト表示される。
        - ドラッグ中のノードは、その子ノード（サブツリー）を伴って移動する。
    - **ドロップ時**:
        - **ノードへのドロップ**: ドラッグされたノードは、ドロップ先のノードの子となる。
            - ドラッグされたノードの既存の親からのエッジは削除される。
            - ドロップ先のノードからドラッグされたノードへの新しいエッジが作成される。
        - **エッジへのドロップ**: ドラッグされたノードは、ドロップされたエッジの間に割り込む。
            - ドロップされたエッジは削除される。
            - ドロップされたエッジのソースノードからドラッグされたノードへの新しいエッジが作成される。
            - ドラッグされたノードからドロップされたエッジのターゲットノードへの新しいエッジが作成される。
            - ドラッグされたノードの既存の親からのエッジは削除される。
- **制約**:
    - 循環参照（サイクル）が発生するようなドロップは許可しない。
    - 自身の子ノードや子孫ノードへのドロップは許可しない。
    - ドロップ先のノードが既にドラッグされたノードの親である場合、操作は無効。
- **目的**: マウス操作でツリー構造を素早く再編成し、思考の流れを妨げない直感的なUIを提供する。

## 27. [S-027] ドラッグ＆ドロップによる構造的順序変更 (Reorder via Drag)
- **概要**: 通常のドラッグ（配置モード）により、兄弟ノードの間などの空きスペースにドロップした場合、そのノードの論理的な並び順を変更する。
- **挙動**: 
    - ドロップされた地点の Y 座標を Yjs の共有データに保存する。
    - 自動レイアウトは保存された Y 座標に基づき兄弟ノードを再ソートし、1, 3, 2 のような新しい順序で整列させる。
    - **注意**: 自動レイアウト有効時でも、ドラッグ操作による位置（順序）の編集を許可する。

## 28. [S-028] ドラッグ操作のモード分離 (Modifier-based Drag)
- **通常ドラッグ (No Modifier)**:
    - 自動レイアウト OFF 時：純粋な位置移動として機能する。構造変更は行わない。
    - 自動レイアウト ON 時：位置変更は保存されず、ドロップ後に元の自動配置に戻る（またはドラッグ不可）。
- **Shift + ドラッグ**:
    - レイアウトモードに関わらず、[S-026] および [S-027] の構造変更ロジックを有効にする。
- **目的**: エッジを選択して削除キーを押す手間を省き、「ツリーから外す」という動作を物理的な移動で完結させる。

## 31. [S-032] クリップボードからのノード追加 (Paste Node from Clipboard)
- **概要**: クリップボードにコピーされたテキスト内容を解析し、新しいノードとしてキャンバスに追加する。
- **階層インポート ([S-033])**: タブまたはスペースでインデントされた複数行テキストを解析し、ツリー構造として一括追加する。
    - インデントが深い行は、直前のインデントの浅い行の子ノードとして接続される。
    - 外部ツール（Excel, Notion, テキストエディタ）のアウトライン形式をそのまま取り込める。
- **初期配置**: 選択ノードがある場合はその子として、ない場合はルートとして配置。

## 32. [S-034] 階層構造のコピー (Copy Hierarchy to Clipboard)
- **概要**: 選択中のノードとその子孫ノードを、階層構造を維持したテキスト形式でコピーする。
- **フォーマット**:
    - インデント（タブ文字）を利用したアウトライン形式。
    - `親ノード`
    - `\t子ノード`
    - `\t\t孫ノード`
- **目的**: ツール内で作成した図面構造を、ドキュメントや表計算ソフトへ構造を保ったまま書き出せるようにする。

## 22. [S-022] MCPサーバー連携
- **概要**: AIアシスタントが MCP を介して図面データを取得・編集できるツール群を提供する。
- **マルチクライアント対応**: 複数のAIクライアント（エージェントやインスペクター）からの同時接続を許可し、SSE（Server-Sent Events）トランスポートを用いて独立したセッションとして管理する。
- **自動再起動機能**: 開発環境において、サーバーコードの変更を検知して自動的にプロセスを再起動（--watch）し、最新のツール定義を即座にクライアントへ公開する。
- **提供ツール (Tools)**:
    - `read_graph`: 現在の全ノード（ID、ラベル、クラス属性、座標）とエッジの一覧を取得する。
    - `add_node`: 新しいノードを図面に追加する。ラベルに加え、ノードクラス（属性）の指定を可能にする。
    - `update_node`: 指定した ID のノードのラベルまたはノードクラス（属性）を更新する。
    - `delete_node`: ノードおよび関連するエッジを削除する。
    - `connect_nodes`: 2つのノード間にエッジを作成する。
- **ユースケース**: 
    - AIが Markdown 仕様書を読み込み、自動的に [S-xxx] ノードを図面に配置する。
    - 複雑なグラフ構造の整合性を AI がチェックし、不足しているエッジを提案・追加する。
- **検証手順 (Acceptance Criteria)**:
    - [ ] `curl -i http://localhost:3000/sse` で接続した際、一意な `sessionId` を含むエンドポイントが返されること。
    - [ ] インスペクターと Gemini CLI を同時に接続し、一方の操作が他方やブラウザにリアルタイムに反映されること。
    - [ ] `add_node` で `nodeClass` を指定した際、ブラウザ上のノードが正しい色とバッジで表示されること。
    - [ ] `update_node` でラベルを変更した際、既存の ID が維持されたまま内容が更新されること。
    - [ ] `delete_node` 実行時、対象ノードに繋がっていたエッジも同時に消滅すること。

## 29. [S-030] ローカル・セレクション（独立したフォーカス管理）
- **概要**: 複数ユーザーで共同編集している際、どのノードを選択しているか（フォーカス）の状態は各ユーザーのブラウザ内で完結し、他のユーザーには影響を与えない。
- **挙動**: 
    - Aさんがノードを選択しても、Bさんの選択状態は変わらない。
    - ノードの追加（Enter/Insert）や削除（Delete）は、各ユーザーが「ローカルで選択しているノード」を基準に実行される。

## 30. [S-031] ゴーストレイアウト・プレビュー (Ghost Layout Preview)
- **概要**: 自動レイアウト ON の状態でノードをドラッグしている間、挿入予定の「スロット（ノード間の隙間）」を視覚化する。
- **挙動**: 
    - 兄弟ノード間の論理的な挿入位置を計算し、その「中間地点」にガイドを表示する。
    - マウスが特定のノード間にある間、ガイドは固定され、順序が入れ替わる境界を越えた瞬間にのみ次のスロットへ移動する。
    - ドロップ（ドラッグ終了）と同時にゴーストノードは消去される。

## 33. [S-035] 単一テキストファイルでの図面入出力 (Single File Diagram I/O)
- **概要**: 図面全体（ノードとエッジ）を単一のMarkdown形式テキストファイルとしてインポートおよびエクスポートする。
- **ファイル形式**: カスタムMarkdown形式。
    ```markdown
    # プロジェクト名

    ## Nodes
    - [S-001] ルートノード1
        - [S-002] 子ノードA
            - [S-003] 孫ノードX
        - [S-004] 子ノードB
    - [S-005] ルートノード2

    ## Edges
    - S-001 -> S-005 [type=関連]
    - S-002 -> S-004 [type=依存]
    ```
- **目的**: 図面データのバージョン管理、共有、外部ツール（テキストエディタ、Gitなど）との連携を簡素化する。

## 34. [S-036] 参加者間での視点同期 (View Sync / Present Mode)
- **概要**: プレゼンター（配信者）の画面操作（パン・ズーム）を、他の参加者の画面にリアルタイムで反映させる機能。
- **モード**:
    - **プレゼン開始**: 自身の視点情報（座標・ズーム）を Yjs を通じて全ユーザーに配信する。
    - **フォローモード**: 配信されている視点情報を受け取り、自身のキャンバスを自動的に移動・拡縮させる。
- **同期対象**:
    - キャンバスの中心座標 (x, y)
    - ズーム倍率 (zoom)
- **UI**:
    - ツールバーに「プレゼン開始/停止」ボタンを追加。
    - プレゼン配信中は、他のユーザーの画面に「フォロー中」のインジケーターを表示し、任意で解除可能にする。
- **自動解除**: フォロー中にユーザー自身がキャンバスを操作した場合、意図的な確認作業とみなしフォローを自動的にオフにする。

## 35. [S-037] プレゼンターのマウスポインタ同期 - Done
- **概要**: プレゼンターがキャンバス上で指し示している場所を、他の参加者の画面にリアルタイムで表示する。
- **挙動**:
    - プレゼンターがマウスを動かすと、その座標を同期データに書き込む。
    - フォロワー（追従者）の画面には、プレゼンターの ID に紐づいた「ゴーストカーソル」が表示される。
    - 座標はキャンバスの論理座標（Flow座標）で同期するため、各自のズーム倍率に関わらず正しい位置を指し示す。
- **視覚効果**: カーソルは目立つ色（例: 赤）で表示し、プレゼンターの名前や ID を添える。
- **目的**: オンライン会議等で「ここを見てください」という意図を正確に伝えるため。
- **目的**: 多人数でのレビューや説明会において、特定の注目箇所を正確に共有するため。
